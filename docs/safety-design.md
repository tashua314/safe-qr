# 危険判定ロジック

## 端末内スコアリング例
- Punycode/紛らわしい文字混在（+3）
- IP直打ちURL（+2）
- サブドメイン深さ>3（+1）：ホスト名のラベル数が5を超える場合。主ドメインを2ラベルとする目安で、Public Suffix Listによる厳密な分類ではない。
- パス/クエリ極端に長い（+1〜2）
- 有名ブランド語を含むが公式ドメインでない（+3）
- 疑義TLD（例 .zip .mov）（+1）

合計 → `0-1: safe / 2-3: caution / 4+: danger`  
厳しさ：`high` は +1、`low` は -1（下限0）

単独のIP指定は2点（注意）、ブランド偽装は3点（注意）、疑義TLDは1点（safe）となる。
safeはこのヒューリスティックのしきい値を超えなかった結果であり、サイトの無害性を保証しない。
相対URL、ホスト欠落、HTTP/HTTPS以外はスコア計算前にdangerとし、厳しさ設定によって緩和しない。
パスとクエリの合計長は100文字以下で0点、101〜200文字で1点、201文字以上で2点。

## 外部レピュテーション照会
- 送信：Google仕様で正規化したURLのhost suffix/path prefix候補に対するSHA-256の**先頭4バイト**（base64）。最大30候補。URL全文・完全ハッシュをGoogleへ送信しない。
- 出力：危険/注意/不明（SafetyLevel?）
- フォールバック：タイムアウト/エラー時は**端末内スコアのみ**

## プライバシー
- Google安全性照会ではURL生値を**送信しない**。タイトル取得・ブラウザ表示は対象サイトへのURLを使う通信。hash prefixから候補が推測される可能性があり、GoogleにはIP等の通信情報も届く。
- ログにURL・タイトル・エラー説明を残さない（定義済みイベント、数値エラーコード、処理時間のみ。詳細はlogging-policy.md）

詳細とPSL snapshot、TTL、検証は [reputation-design.md](reputation-design.md) を参照。
