# Issue #8の検証と申請資料の更新計画

1. 修正済みの判定・外部照会・同意・設定・ログを統合し、Debug/ReleaseとiPhone/iPad Simulatorで操作を検証する。実機カメラ、ライト、長時間動作・バッテリー、本番API認証、署名配布は別の確認欄に残し、Simulatorの結果を代用しない。
2. メモリ取得失敗を0MBへ変換する既存テストを修正し、測定失敗はテスト失敗にする。DIのキャッシュ参照の反復を新規インスタンスの破棄検証と区別する。
3. 警告の詳細を開いた状態、横画面、小さい画面で開封・拒否ボタンへ到達できるか確認し、必要なら確認カードをスクロール可能にする。確認条件と通信条件は変更しない。変更前後の実画面を保存する。

5. 申請文、審査メモ、プライバシー、利用規約は下書きにする。運営者・窓口・公開URLは利用者が未定と回答済み。年齢レーティング、公開価格/地域、Safe Browsing利用条件を確認してから確定する。
6. Googleの公式利用条件に従い、Google検出の警告だけに出典と脅威の説明リンクを付ける。ローカル・外部失敗/未知だけの警告にはGoogleの危険判定を示さない。リンクにスキャンURLを含めない。
7. キャプチャはGitへ保存し、PRはコミット固定リンクにする。GitHub contentsで存在とハッシュを読み戻す。iPhone/iPadの画像は実際の画面・状態・OS・解像度を記録し、カメラのモック表示を実カメラ画面に見せかけない。
