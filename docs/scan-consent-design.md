# スキャン先への通信と開封確認

Issue #2では、スキャン検証 → 完全評価 → 履歴保存 → 必要な確認 → 開封の順に処理する。外部チェックの待機中はタイトル取得もブラウザー表示も開始しない。注意・危険、外部チェック失敗・未対応情報では確認を必須にする。外部チェックOFF時はローカル評価のみであることを設定画面に示し、ローカルsafeのみ自動開封する。

スキャン履歴は最終判定で一度保存し、拒否時は新たなタイトル取得を行わず、既存履歴があれば過去のタイトルを保持する。履歴からの再訪も現在の設定で再評価し、同じ確認を通す。再訪の訪問回数は開封を許可した場合だけ増やす。タイトル取得は開封許可と同時に一度だけ開始し、更新で訪問回数を増やさない。

各評価には識別子を付ける。待機・確認中の別QR、キャンセル済み評価の遅延結果、同じ決定の二重実行を受け付けない。結果の通知経路を一つにし、確認画面を二重表示しない。確認画面を閉じた後にブラウザーを表示する。

タイトル取得は利用者が許可した元URLだけにGETし、HTTPリダイレクトを追わない。ブラウザー内の遷移はブラウザーの処理であり、このタイトル取得の許可に含めない。タイトル取得の失敗は履歴のURL表示へフォールバックする。

検証は遅延する外部判定・拒否・再スキャン・古い結果・二重開封・タイトル更新・履歴再訪の回帰テスト、リダイレクト先への要求がないこと、警告画面の操作と保存済みキャプチャで行う。実機カメラ・実通信を含む公開前確認はIssue #8で別途管理する。
